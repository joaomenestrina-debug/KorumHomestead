# T0.6 — Split `UI.lua` into one file per screen

**Owner:** Codex · **Reviewer:** Claude · **Sprint:** 0 · **Estimate:** 5 h · **Branch:** `codex/T0.6-split-ui`

## Why

`UI.lua` has ~2,100 lines: the window, the floating icon, the minimap button and ten screens. The 2.0 adds five systems
with new screens; before that, each screen must live in its own file so several people can work at once without
conflicts.

## What to do

A pure move of code. **No behaviour, look, text or number may change.**

1. Create `UI/` with these files, in this load order (add them to `KorumHomestead.toc` in place of `UI.lua`):

   | File | What goes there (from today's `UI.lua`) |
   |---|---|
   | `UI/Common.lua` | the shared locals: `Kit`, `C`, `D`, `V`, `T`, `WIDTH`, `HEIGHT`, `WHITE`, `VDIR`, `Reason`, `Notice`, `Screen`, `GoodTex`, `SetIcon`, `Tier`, `BuildingArt`, `BuildingName`, `Tip`, `UI:Step()` |
   | `UI/Garden.lua` | `CanPlant`, `PaintTile`, `BuildGarden` and its constants |
   | `UI/Barn.lua` | `BuildBarn` |
   | `UI/Market.lua` | `BuildOrders` and its constants |
   | `UI/Settings.lua` | `BuildSettings` |
   | `UI/Village.lua` | `SPOT`, `VIEW_OF`, `Door`, `SPRITE`, `BuildVillage` |
   | `UI/Hall.lua` | `HALL_ROW`, `HALL_GAP`, `Effect`, `BuildHall`, `BuildSource` (Mine and Pond) |
   | `UI/Guide.lua` | `GUIDE_PAGES`, `BuildGuide` |
   | `UI/Workshop.lua` | `RECIPE_*`, `QUEUE_ROWS`, `BuildWorkshop` |
   | `UI/Inn.lua` | `FOLLOWER_*`, `BuildInn` |
   | `UI/Window.lua` | `BUILDERS`, `CRUMB`, `UI:Create` and everything after it except the icon and the minimap button: `PaintPath`, `ShowCoins`, `ShowLevel`, `RefreshHeader`, `Relabel`, `OnSelect`, `Coach`, `RefreshScreen`, `Show`, `Toggle`, `Refresh`, the ticker and `UI:Tick` |
   | `UI/Bubble.lua` | the floating icon and its toasts (`bubble`, `TOAST_HOLD`, `Waiting`, `PlaceBubble`, `PlaceToast`, `NextToast`, `UI:Toast`, `UI:ApplyBubble`, `UI:CreateBubble`) |
   | `UI/Minimap.lua` | the minimap button (`button`, `PlaceButton`, `UI:UpdateBadge`, `UI:ApplyMinimap`, `UI:CreateMinimap`) |

2. **How the files share things.** Each file starts with `local addonName, KH = ...`. `UI/Common.lua` creates the table
   `KH.UI` (today `local UI = {}` + `KH.UI = UI` somewhere) and a private table for the helpers:

   ```lua
   local UI = KH.UI          -- in every file after Common.lua
   local P = UI.P            -- the shared helpers: P.Screen, P.Notice, P.GoodTex, ...
   ```

   Put every shared local of `Common.lua` on `UI.P` and, at the top of each screen file, bring the ones it uses back as
   locals (`local Screen, Notice = P.Screen, P.Notice`). Each `Build*` function is registered on `UI.P.builders`
   (`P.builders.garden = BuildGarden`), and `UI/Window.lua` builds `BUILDERS` from it, so the window needs no list of files.
   Keep `UI.Tier` and `UI.trade` exactly as they are today (other code and the tests use them).

3. **The file lists.** The tests and the simulator have their own list of the addon's Lua files
   (`FILES` in `tests/test_homestead.py`, `HOMESTEAD` in `ferramentas/simulador_ui.py`). Change both to **read the list
   from `KorumHomestead.toc`** (the lines that end in `.lua`, in order), so they never get out of step again.

4. Delete the old `UI.lua`.

## Must not change

- Any text, number, size, position or colour; any saved variable; any global name.
- The other Lua files (`Core.lua`, `Farm.lua`, `Village.lua`, `Works.lua`, `Data.lua`, `Locales.lua`, `Kit.lua`).
