# T1.4 — The order of the day and the streak (`Daily.lua`)

**Owner:** Codex · **Reviewer:** Claude · **Sprint:** 1 · **Estimate:** 4 h · **Branch:** `codex/T1.4-daily`
**Can start now.** Logic and tests only: the screens are T1.5 (Claude), the texts T1.6.

## Why

The 2.0 gives the player a reason to come back every day: one special order a day, at the top of the Market, that pays
much more than a normal one. Delivering it on days in a row builds a **streak**, with an extra prize on days 3, 7, 14 and
30. Missing a day only sets the streak back to zero; nothing else is lost (rule of the project: nothing punishes a player
who was away). The best streak is kept.

## What to do

### 1. Numbers in `Balance.lua`

Add `B.DAILY` after `B.ORDERS`, with a one-line comment per field:

```lua
B.DAILY = {
    qtyMultiplier = 2,        -- the order of the day asks for twice the herbs of a normal order
    payMultiplier = 2.5,      -- and pays 2.5x what a normal order of that size pays (coins and xp)
    streak = {                -- extra prize when the streak reaches the day (once per streak)
        [3]  = {coins = 1.0},             -- +100% of the day's coins
        [7]  = {coins = 1.0, rare = 1},   -- +100% and one rare keepsake
        [14] = {coins = 2.0, rare = 1},
        [30] = {coins = 3.0, rare = 2},
    },
    rareEvery = 7,            -- after day 30: one rare keepsake every 7 days of streak (37, 44, ...)
    rareItem = 13468,         -- the keepsake: Black Lotus (game item, for its icon and name)
}
```

**Changed on 17/11 (excess of gold):** `payMultiplier = 1.25`, new `xpMultiplier = 2.5`, and the streak prizes give `xp`
(a share of the day's xp) instead of `coins`. See `Balance.lua`.

These values were a **proposal**; the owner approves them in T1.2 (Monday 23/11); if other numbers are chosen, only this table
changes. Write the code so nothing else depends on the exact values.

### 2. `Daily.lua` (new file, loaded right after `Farm.lua` in the `.toc`)

`KH.Daily` with this API (the UI of T1.5 will call only these):

| Function | Does |
|---|---|
| `Daily:Ensure()` | If `db.daily.day ~= KH.Day()`: makes the order of today (see below), `done = false`, and if the streak is broken (`lastDone < today - 1`) sets `streak = 0`. Returns `true` when it changed the day. If the clock went **back** (`KH.Day() < db.daily.day`), it changes nothing. |
| `Daily:Order()` | The order of today (`{plant, qty, coins, xp, npc}`), after `Ensure()`. |
| `Daily:Done()` | `true` if today's order was already delivered. |
| `Daily:CanDeliver()` | Not done and the Barn has `qty` of the herb. |
| `Daily:Deliver()` | Takes the herbs from `db.crops`, pays `coins * KH.Village:PayBonus()` plus the streak prize, adds the xp (`KH.Farm:AddXP`), counts the streak, sets `done`, updates `best`, `stats.earned`, `stats.delivered` and `db.daily.rare`. Returns `true, result` with `result = {pay, xp, streak, bonus, rare}` (`bonus` = the extra coins of the streak prize, `rare` = keepsakes given now; 0 when none); or `false, reason` (`"done"`, `"missing"`). |
| `Daily:Streak()` | The streak **as it stands today**: the saved `streak` if `lastDone >= today - 1`, else 0 (so the UI shows 0 at once after a missed day, even before `Ensure`). |
| `Daily:NextPrize()` | The next streak day with a prize and how many days are missing: `day, missing` (after 30, the next multiple of `rareEvery` after 30). |

**Making the order of today:** reuse `KH.Orders:Make()` (same herb choice by level) and then multiply: `qty` by
`qtyMultiplier` (rounded down), `coins` and `xp` recomputed for the new `qty` and multiplied by `payMultiplier`. Do not
copy the formula of `Make`: if you need the per-unit values, take them from the plant (`D.Plant(id).sell`, `.xp`) and
`B.ORDERS`.

**Streak count on delivery:** `streak = (lastDone == today - 1) and streak + 1 or 1`; `lastDone = today`;
`best = max(best, streak)`. The prize of `B.DAILY.streak[streak]` (or the `rareEvery` rule after 30) is paid on the
delivery that reaches that day.

**Ticking over midnight while playing:** call `Daily:Ensure()` on `PLAYER_LOGIN` (after `Orders:Ensure()`) and at the
start of `UI:Tick()` in `UI/Window.lua` (one line; that is the only UI file you touch).

### 3. Saved data

New field in the defaults of `Core.lua`:

```lua
daily = {day = 0, order = nil, done = false, streak = 0, best = 0, lastDone = 0, rare = 0},
```

`rare` is the count of keepsakes earned (the F4 Herbarium will show them; for now they are only counted). No migration
is needed: the defaults fill the field in older saves. Do not raise `KH.SCHEMA`.

## Tests (`tests/test_daily.py`)

Use the clock of the T0.9 tests (`date` reading `NOW`, see `test_homestead.py` around line 866) and move `NOW` by days.
At least:

- a new day gives a new order; the same day keeps it (even across `/reload`: a new `ADDON_LOADED` with the saved table);
- the order of the day asks `qtyMultiplier` times and pays `payMultiplier` times a normal order of the same herb;
- delivering takes the herbs, pays, counts the streak; delivering twice the same day fails with `"done"`;
- 3 days in a row → streak 3 and the bonus of day 3 paid once; day 7 gives `rare`;
- one day missed → `Streak()` is 0 right away, the next delivery starts at 1, `best` keeps the old record;
- the clock going back one day changes nothing;
- crossing midnight with the window open: `UI:Tick()` makes the new order;
- the 1.0.1 save (`tests/fixtures/save-1.0.1.lua`) loads with `daily` filled and an order for today.
